# 本机与线上部署

本机 Python 执行器负责读取个人资料和调用模型，网页负责阅读、检索、提交任务和显示结果。线上采用 Sites 的登录保护、D1 队列与 R2 快照存储。迁移数据本身不要求先部署线上。

## 只在本机使用

导入自己的数据，启动 `.\start.ps1 -Config "配置文件完整路径"`。`cloud_url` 留空，网页任务使用本机队列。默认只监听 `127.0.0.1`。

配置优先级是：显式 `-Config`／`--config`、已选工作区 `.workspace-active.json`、源码目录 `config.local.json`、环境变量 `OW_CONFIG`。没有可用配置时进入待导入状态，不猜旧电脑的目录或站点。相对路径按配置文件所在目录解释。`port` 和 `web_port` 分别控制 API 与网页端口，也可以用启动参数覆盖。同一源码目录共享网页代理配置，不能同时切换多个知识库或 API 端口；并发实例使用独立源码副本。

## 配置自己的来源

首次建库的来源为空，不会自动扫描桌面、下载或其他人的目录。在私有配置中只填写自己希望收录的现有目录，例如：

```json
{
  "watch_roots": [{"name": "资料收件箱", "path": "../资料收件箱", "max_depth": 3, "max_files": 3000}],
  "memory_roots": [],
  "feishu_enabled": false,
  "note_project_aliases": {"项目甲": ["项目甲", "代号甲"]}
}
```

这里展示的是配置片段，不替代初始化生成的路径和检查点字段。路径按配置文件目录解释；运行数据与知识库须分离。`note_project_aliases` 用于新笔记分组，正文的明确主题及笔记的 `project` 属性也应与实际项目一致。歧义内容留待复核，不靠改日期强行重跑。

启用飞书时再设置 `feishu_enabled: true`、自己的授权和 `feishu_video_owner`；当前只登记新增入口元数据。`generated_roots`、`old_output_roots`、`runtime_roots` 用于排除输出和运行目录，不应当成新的来源目录。

## 建立自己的线上入口

1. 在 Sites 为自己的账号建立私有站点，使用 `web/` 源码，创建名为 `DB` 的 D1 绑定和 `BUCKET` 的 R2 绑定。
2. 应用 `web/drizzle/` 中的数据库迁移，再按 Sites 的部署流程构建和发布。表结构定义位于 `web/db/schema.ts`。
3. 保持登录保护；本站 API 依赖平台访问控制，不能直接当成无需认证的公网 API 部署。
4. 将自己的网址写入私有配置的 `cloud_url`。从平台取得自己的服务访问令牌，在本机通过 `py -3 -X utf8 configure-service.py --config "配置文件完整路径"` 的隐藏标准输入提交 `{"token":"自己的令牌"}`。不要放进命令行参数、仓库或网页代码。
5. 从当前 Codex 会话重新启动本机执行器，确认网页显示已连接，再提交一个小任务并核对本机笔记和线上结果。

令牌使用 Windows DPAPI 保存到配置的运行数据目录，只适用于当前机器用户。新机需重新授权。平台服务访问使用 `OAI-Sites-Authorization`；不支持自行伪造登录状态。

仓库内 `web/.openai/hosting.json` 仅声明通用存储绑定，不包含作者个人站点 ID。`OW_LOCAL_API` 只用于本地网页代理；线上不要设置它，也不要上传本机 `.dev.vars`。

## 代码仓库与部署工作副本

GitHub `main` 是维护源码的唯一主线。Sites 若需要独立 Git 根目录，应从主线复制 `web/` 到独立的、忽略的部署工作目录，再在该目录绑定自己的站点；不要在受 GitHub 跟踪的 `web/` 中再建立嵌套 Git 仓库。发布前同步主线源码，保留平台要求的站点配置和私有授权，按平台回读实际部署状态。

本机现有的私有部署工作副本可保留在 `output/sites-source/`，但它不随 GitHub 或资料迁移包分发。新机器需要自行创建部署工作副本；已经发布的线上站点不因本机代码迁移被删除或覆盖。

## 切换执行器

旧机任务结束后用 `.\stop.ps1 -Config "配置文件完整路径"` 停止旧执行器（网页保留），新机导入笔记和检查点，再配置云端授权。确认新机读到同一资料后才接回线上任务。已有队列和线上快照保留在原站点；本地迁移包不复制待执行任务。需要回退时，先停新执行器，使用保留的旧机资料与匹配版本恢复，避免同时写入。
