# 2026-06-02 可迁移 AI 系统与产品缺陷修复

## 本轮输入

- 用户要求学习视频《3层Obsidian文件系统，如何适配所有AI？随时迁移》。
- 视频材料抓取结果：官方 AI 摘要不可用，官方字幕为空；已用 ASR 获取转写。
- 可确认核心：ACT 知识资产、AI 身份文件、Skills / SOP，本地 Markdown 保存，可迁移、可复用、随时切换 AI 工具。

## 产品判断

本项目不应新增第四个首页入口。三层思路应进入底层组织原则：

- `ACT 知识资产` 对应添加资料、索引、证据和 Obsidian 笔记。
- `AI 身份文件` 对应用户偏好、协作边界和上下文包中的身份摘要。
- `Skills / SOP` 对应三主操作流程、测试基准和可迁移执行步骤。

继续保留三操作闭环：

- 添加资料必须真实入库。
- 搜索回顾必须找到已沉淀证据。
- 生成 AI 上下文包必须从证据生成可复制 prompt。

## 本轮修复

- 修复 `open-path`：只打开白名单根目录内路径；Obsidian vault 内 Markdown 走 `obsidian://open`；越权路径返回错误。
- 修复 GUI E2E 清理：新增 `Stop-GuiServer`，测试结束后同时清理启动进程和监听端口。
- 新增三层迭代计划：`docs/PORTABLE_AI_SYSTEM_ITERATION_PLAN.md`。
- README 从旧“站点式知识流”收敛回三操作闭环。
- DESIGN 从“知识流/知识详情”改为“可迁移三层/结果详情”。
- `project_quality.py` 增加三层原则和新计划文档质量门禁。

## 自查问题

- 做到了视觉清晰阅读友好了吗？本轮没有重做视觉，但清理了 README/DESIGN 中会误导 UI 方向的旧知识流主线。
- 做到了总结归纳到位，没有废话不遗漏关键信息了吗？本轮把视频思路压成三层映射，并明确哪些进入项目、哪些不新增入口。
- 发给别人能看懂吗？计划文档按来源依据、项目判断、结构映射、本轮修复和下一阶段拆分，能独立阅读。
- 传到 Codex 指引性足够吗？质量测试已要求公开文档包含 ACT 知识资产、AI 身份文件、Skills / SOP，后续 Codex 不应再把它混成知识流功能。
- GUI 双向交互方便吗？本轮修复来源路径点击，降低“看得到但打不开”的交互断点。
- 信息内容容易编辑吗？所有新增计划和原则都是 Markdown，可直接在 Obsidian 或仓库中编辑。
- 展示的方式足够方便吗？结果详情仍需下一轮继续优化排版，本轮只修复打开路径和文档方向。
- 信息集关联有做吗？本轮用三层映射把添加资料、搜索回顾、AI 上下文包关联到 ACT/身份/SOP。
- 能让人发散性思考吗？下一阶段计划明确身份文件和 SOP 模板化，能引导继续把个人习惯沉淀成可迁移资产。

## 剩余风险

- AI 身份文件和 Skills / SOP 目前还是计划与原则，尚未实现为模板和初始化产物。
- 本轮没有新增语义检索；搜索准确性仍依赖现有严格关键词和证据排序。
- GUI 视觉没有本轮重绘，需要靠后续 Playwright 截图继续验收。
