# 添加资料完成态阅读体验优化

## 范围

- 只优化 `添加资料` 完成态的阅读结构。
- 不新增 GUI 入口、不改后端 action、不扩展功能。

## 改动

- 将完成态从通用搜索结果结构改为入库报告结构：`本次入库结果`、`在 Obsidian 里怎么找`、`推荐搜索词`、`入库来源`、`入库产物`。
- 增加入库统计卡：扫描文件、独立文件索引、源文件改动、生成产物。
- 添加建议阅读顺序：先看整理记录，再看文件索引目录，最后用推荐搜索词测试找回。
- 入库来源不再显示成 `命中证据`，改为 `入库来源 / 为什么入库 / 来源摘录`。
- 入库产物默认只展示最常用路径，其余产物提示已保留，避免长路径淹没主要结论。
- Playwright QA 增加 `organize-completion.png`，专门保存添加资料完成态截图。

## 自查

- 做到了视觉清晰阅读友好了吗：完成态第一屏能看到入库结论、数量、阅读顺序和 Obsidian 入口。
- 做到了总结归纳到位，没有废话不遗漏关键信息了吗：保留扫描数量、索引数量、源文件安全边界和产物位置。
- 发给别人能看懂吗：展示语义从 `命中证据` 改为 `入库来源`，更接近用户刚完成添加资料后的真实问题。
- 传到 Codex 指引性足够吗：截图和 QA 结果能复现真实路径入库、独立索引、搜索找回链路。
- GUI 双向交互方便吗：推荐搜索词可直接进入搜索回顾；路径可复制或打开。
- 信息内容容易编辑吗：实际内容仍写入 Obsidian Markdown，GUI 只做可读入口。
- 展示的方式足够方便吗：长路径单独放入路径 chip，产物列表收敛展示。
- 信息集关联有做吗：整理记录、文件索引目录、推荐搜索词和入库来源在同一完成态内关联。
- 能让人发散性思考吗：完成态指向“如何找回”和“下一步搜索”，但不额外塞新功能。
