# 2026-06-02 AI 上下文包接入身份文件

## 本轮目标

上一轮已经把 `AI 身份文件` 和 `Skills-SOP` 做成可安装模板。本轮继续推进核心闭环：生成 AI 上下文包时，不只引用证据来源，还要带上已整理的身份偏好和上下文边界。

## 本轮改动

- `knowledge_assistant.extract` 新增 AI 身份文件读取。
- 读取范围固定为 `knowledge_root/AI 身份文件/` 下的三个文件：
  - `AI_IDENTITY.md`
  - `AI_COLLABORATION_RULES.md`
  - `AI_CONTEXT_BOUNDARY.md`
- `preview` 模式会在 `debug.identity` 中返回身份文件数量和路径，并在 summary 中提示身份文件是否可用。
- `generate` 模式会把 `AI 身份文件摘要` 写入 prompt、runtime Markdown、Obsidian Markdown 和 `context-package.json`。
- 没有证据来源时仍拒绝生成上下文包；身份文件只补充偏好和边界，不替代证据。

## 产品意义

- 新 AI 对话拿到的不再只是资料摘录，还能知道使用者偏好、协作规则和安全边界。
- 身份文件被纳入核心产物，但没有新增 GUI 入口，避免首页再次变复杂。
- 上下文包更接近“可迁移 AI 工作流资产”，可以跨 Codex、其他 AI 工具和新机器复用。

## 自查问题

- 做到了视觉清晰阅读友好了吗？本轮不改视觉；Markdown 新增 `AI 身份文件摘要` 独立 section，避免塞进来源摘要。
- 做到了总结归纳到位，没有废话不遗漏关键信息了吗？摘要只提取身份文件的压缩内容、路径和边界，不输出完整长文。
- 发给别人能看懂吗？prompt 中明确区分当前需求、已整理上下文、AI 身份文件摘要、使用要求和安全边界。
- 传到 Codex 指引性足够吗？足够；Codex 能看到来源路径、用户偏好和禁止项。
- GUI 双向交互方便吗？preview 会提示身份文件是否可用；仍然需要下一轮把这个提示做成可见字段。
- 信息内容容易编辑吗？身份文件仍是普通 Markdown，用户可直接改。
- 展示的方式足够方便吗？Markdown 和 prompt 都有独立身份摘要区；GUI 结果卡仍需继续优化展示。
- 信息集关联有做吗？证据来源和身份文件被同时写进上下文包，但身份文件不算证据来源。
- 能让人发散性思考吗？身份文件摘要能提示用户继续完善角色、偏好和上下文边界。

## 剩余风险

- GUI 结果卡还没有单独展示“本次上下文包含身份文件”。
- 身份文件摘要目前是规则化压缩，不是语义总结。
- 只读取固定三个文件名，暂不支持自定义身份文件列表。
