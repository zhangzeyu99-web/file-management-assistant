# 2026-06-02 三操作产品缺陷修复迭代

## 本轮目标

继续修复三操作闭环中会让用户误判“功能无效”的问题。重点不是增加新入口，而是让已有三个入口在真实数据和 GUI 操作里更可信。

## 缺陷与修复

### 1. 搜索回顾等待体验不明确

缺陷：真实 vault 首次检索需要建立索引，但页面只禁用按钮，不解释正在做什么。

修复：GUI 点击动作后立即渲染处理中状态；搜索回顾显示 `正在建立索引`，并说明首查建立本地索引、连续搜索复用缓存。

### 2. 打开来源会破坏当前结果上下文

缺陷：`打开来源` 原来复用通用 action 渲染，会把搜索结果替换成 `open-path` 的返回结果。

修复：打开路径改为 `openPathWithoutReplacingResult()`，只在当前结果上方显示行内状态，不覆盖证据卡。

### 3. 加入上下文包缺少可见反馈

缺陷：点击 `加入上下文包` 后只滚动到提取区，用户看不出是否已选中来源。

修复：新增 `renderSeededExtractSource()`，在 AI 上下文包区显示 `已加入上下文包候选`、候选来源路径和 `确认生成上下文包` 按钮。

### 4. 真实 vault 检索性能

缺陷：watch root 使用全量 `rglob("*")`，会扫描大量无关文件。

修复：只枚举 Markdown/TXT；增加 review 索引缓存；organize 写入后清缓存。
