# 测试原则

测试目标：证明三操作闭环真实可用，而不是按钮能点。

## 必测闭环

1. 添加资料必须真实入库，并为每个可读文件生成独立索引条目。
2. 搜索回顾必须能找到已沉淀证据，返回一句话答案、命中词、证据摘录和来源路径。
3. 生成 AI 上下文包必须从确认来源生成可复制 prompt。

## 失败标准

- 搜索只命中弱相关内容却显示成功。
- 没有证据也生成上下文包。
- GUI 默认展示 JSON 或把路径塞进大段正文。
- 首页重新出现知识流、提醒、诊断、旧功能入口。
- 公共状态接口重新暴露 `knowledge_feed`，或 GUI 继续读取旧的文件扫描统计。
- GUI E2E 因不存在的旧调试框、旧按钮或旧入口产生长时间等待。

## 性能基准

- GUI E2E 的单个核心动作应在秒级完成；如果出现 30 秒级等待，优先检查测试脚本是否仍在等待旧 DOM。
- E2E wrapper 必须有 run-code 超时、stdout/stderr 证据和进程清理。
- 通过测试不等于体验合格；动作耗时、结果可读性和失败态都要记录。
- 真实 vault 搜索首查可以建立索引，但连续搜索必须复用索引；如果每次查询都重新扫描大目录，视为产品缺陷。
- watch root 只能枚举可索引候选文件，例如 Markdown/TXT；不得用 `rglob("*")` 扫全目录后再筛选。

## 真实数据验收

固定查询：

- `运营sop`
- `github仓库`
- `简历线程`
- `Obsidian助手`
- `不存在的测试关键词`

运行：

```powershell
python -X utf8 scripts\run-real-query-qa.py
```

合格标准：

- `review` 必须返回答案、命中词、证据摘录和来源路径。
- `extract` 只能跑 preview，不生成上下文包文件。
- 无匹配查询必须返回未找到，不能用最近笔记伪装成结果。
- `Obsidian助手` 这类查询不能让迭代日志、QA 记录或测试报告排到首条；应优先教程、指南、知识卡或真实工作记录。
- 同一文件不能因为同时来自 vault 和 watch root 而在索引里重复出现。
