# 每周自动归档

本页规定周任务的时间、接续与验收；内容准入、标题正文、去重、分类和交付要求统一执行 [归档入库规则](ARCHIVE_RULES.md)。

## 在自己的 Codex 设置任务

克隆或迁移不会复制账号内定时任务。确认项目已能启动、已选正确工作区后，在该项目的 Codex 对话中发送：

> 每周五下午 7 点（Asia/Shanghai，北京时间）在这条对话执行知识库归档。按项目 AGENTS.md、docs/ARCHIVE_RULES.md 和 docs/WEEKLY_ARCHIVE.md 执行，覆盖至本期周五19:00，从上次成功验收位置续接；漏跑补齐，保留未完成来源。使用现有唯一队列、复核并真实读回后验收，按具体主题汇报。

由 Codex 使用原生定时任务功能保存，读回核对名称、时间、启用状态和目标对话。已有同一任务就更新，不重复创建。运行时需电脑开机、桌面运行、授权有效及本机执行器可用；本地资料更新不在没有执行器的线上服务器独立运行。

## 时间边界

- 本期终点固定为应运行的周五 19:00；晚启动沿用该终点，之后的内容留给下期。
- 从 `weekly-archive.json` 的上次成功终点接续。漏跑两周补两周，不机械裁成最近七天。
- 首次没有周成功水位时，以前七天与既有基线中较晚者作为本期说明起点；现有来源检查点继续有效。
- 未登记的新路径、未完成轮次等旧欠账不因早于说明起点被丢弃。新复制资料可能保留旧修改时间，仍按新路径判断。
- 同期失败沿原窗口、原身份重试。跨周仍失败的旧任务保留引用，新一期可以处理后续新增；用户取消的任务不自动恢复。
- 成功的单项处理保留。部分覆盖、质量不合格、读回或同步失败不推进整期水位。

## 执行顺序

1. 读取项目协作说明、共同归档规则与本文，解析当前配置，检查 API、任务与真实来源连接；不猜管道或线程 ID。
2. 执行 `queue`，复用唯一 `update` 任务；用 `status` 分次检查状态。等待和部分完成不能写成成功。
3. 阅读本期全部知识产物，只查看判断重复所需的相关旧主题，按共同标准修正标题、概括、冗余、状态、分类和来源。没有复用价值的内容不进入知识视图。
4. 如需合并，用安全整理入口生成计划；执行器无活动任务时停止，应用后重启，等待索引和线上更新。不能运行历史一次性全库清理脚本。
5. 逐篇本机读回并核对线上脱敏副本。空闲执行器约 45 秒刷新变更；同步滞后时等待并复查，不重跑已完成来源。
6. 全部通过后准备私有复核回执，调用 `accept`；它重新核对真实任务、文件、本机 API 与远端正文，成功才推进周水位。

在项目根目录运行，默认沿用当前已选工作区：

```powershell
py -3 -X utf8 scripts/weekly_archive.py queue
py -3 -X utf8 scripts/weekly_archive.py status
py -3 -X utf8 scripts/weekly_archive.py accept --job <实际任务ID> --review <私有复核回执.json>
```

可加 `--config <自己的配置>`；迁移后通常使用已选的 `workspace.json`。`queue --until <带时区ISO时间>` 可补指定一期，不能指定未来。默认终点为最近已到达的周五 19:00。此入口不另起调度器或知识写入器。

## 复核回执与成功条件

回执包含 `quality_checked: true`、全部 `note_ids`、具体 `topics` 和非空 `assessment`。有跨期旧任务时，填写 `pending_debt_checked: true` 和准确的 `pending_job_ids`，确认新增任务是否已补齐它们。不能没读内容就填通过。

整期成功必须同时满足：

- 实际任务为 `completed`，无来源错误、部分覆盖和未解决的检查点欠账。
- 本期内容复核通过，入口、分类、来源和旧链接正确。
- 本机实际正文与 API 一致；线上同步完成，远端正文与本机脱敏结果一致。

没有新增也需来源检查与同步成功才可验收。官方接口超限、活跃列表窗口和权限问题按实际影响记录，已保存成果保留；不能把受限来源写成“无新增”。

## 持久记录与交付

记录保存在当前配置的 `data_root`：

| 记录 | 用途 |
|---|---|
| `runs/<身份>/journal.json` | 冻结窗口、保存结果、重试身份 |
| `weekly-active.json` | 当前与跨期未完成任务的接续入口 |
| `weekly-archive.json` | 最近成功终点及验收依据，仅通过 `accept` 推进 |
| 原有来源检查点与 `receipts` | 逐来源、逐轮次的成功身份与欠账，不能被全局日期替代 |

周成功记录随迁移包保留；旧活动队列不迁移。报告给当前对话的内容是本期范围、具体更新主题、阅读入口和未完成原因，区分新线程、旧线程续聊、自动任务及飞书入口。个人数据和复核回执不提交 Git，不改站点访问权限，不另发邮件或即时消息。
